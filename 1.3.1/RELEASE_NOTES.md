# Ascora ADE 1.3.1

What's new?

### Added
- **Unsloth local provider** — added a dedicated provider page with server URL, required API key, authenticated connection checks, server model discovery, and an official installation link. Unsloth is selectable and hideable in the composer, remembers model choices per workspace/chat, and reports its connection and local token usage in the status bar and Analytics. Supports streaming chat and native tool calls; GGUF templates that explicitly reject native tools fall back to Ascora's existing text-tool protocol without dropping tool history. Tested against a local Unsloth server with LFM2-1.2B.
- **CLI limits page in Settings** — a dedicated Limits tab immediately after Agent Providers checks installed, signed-in CLIs, including providers hidden from the composer menu. Codex, Claude, and Antigravity show remaining allowances, reset dates, and the last data refresh time, with manual refresh and automatic updates every minute. Providers without a supported quota feed are marked as unavailable; a failed check does not block other providers.
- **Separate Gemini reasoning selector for Antigravity** — Gemini 3.8, 3.7, and 3.6 Flash now offer Low / Medium / High beside the model picker and in provider settings. Gemini 3.1 Pro offers its supported Low / High variants. Model and reasoning choices persist per workspace and chat, and apply to subsequent turns in resumed conversations.
- **Antigravity account quotas** — reads the local runtime's weekly and five-hour quota groups for Gemini and Claude/GPT models, including exhausted allowances and reset timestamps, in both the provider settings page and the shared Limits tab.
- **Full-page application settings view** — replaced modal preference dialogs with a comprehensive, full-screen Settings workspace accessible from the left rail and keyboard shortcuts. Features dedicated tabbed sections for Providers, Appearance, Languages, and Developer Tools.
- **Provider setup, introspection, and visibility manager** — added native discovery and health checks for all CLI agent backends (Antigravity, Claude, Codex, Copilot, Gemini, GLM, Grok, LM Studio, OmniRoute, Ollama, OpenCode). Inspect installed versions, active server ports, authentication tokens, and installation guides in one place. Any provider can be toggled on or off to declutter the left rail and the composer provider selector.
- **Compact Codex activity panel** — consecutive Codex reasoning, command, and file-change events are now grouped into a single collapsible work log modeled on the Codex UI. While a turn is active the panel shows a localized “Thinking” heading and live one-line action rows; completed turns keep a compact “Work log,” long commands truncate cleanly, and each row can expand to reveal the existing command output, errors, approvals, or side-by-side diff without duplicating the standalone thinking indicator. The panel and its running/completed/error labels are localized in all eleven interface languages.
- **Chinese (Mainland), Korean, Japanese, Polish, and Hindi interface languages** — the language switcher now includes Simplified Chinese (`zh` / `zh-CN`), Korean, Japanese, Polish, and Hindi catalogs covering the full UI, with CJK and Devanagari font fallbacks and date/number formatting mapped to each matching locale.
- **Grok Build CLI backend** — xAI's `grok` coding agent is now a selectable agent provider (`grok -p --output-format streaming-json`), with auto-detect from PATH / `~/.grok/bin`, optional binary path, model and reasoning-effort pickers, permission modes (`plan` / `default` / `acceptEdits` / `auto` / `dontAsk` / `bypassPermissions`), Sign in / Sign out (`grok login` / `grok logout`) with account display from `~/.grok/auth.json`, session resume via `--resume`, and the same normalized tool/reasoning cards as Codex and Claude. SuperGrok / X Premium+ subscription auth or `XAI_API_KEY` are both supported.
- **Google Antigravity CLI integration** — Google Antigravity is now a selectable agent provider driven via its local runtime, with a Python SDK path for API-key authentication. Supports auto-detection of `agentapi.bat` and `language_server.exe`, account verification through the running local server, Gemini model and reasoning selection, conversation resumption, streaming text and tool calls, Composer and Connection Settings integration, and status-bar health reporting.
- **Antigravity multi-model support** — the Antigravity model picker now includes Claude Sonnet 4.6, Claude Opus 4.6, and GPT-OSS-120B alongside the existing Gemini tiers. Models are organized into optgroup categories (Gemini / Claude / GPT) in both the Composer and Connection Settings.
- **Terminal quick-access button in the activity bar** — a new terminal icon in the left rail opens (or focuses) the local terminal panel in one click, without navigating through the Explorer first.
- **Persistent terminal command history** — the ↑/↓ arrow key command history now survives app restarts, workspace switches, and shell restarts. Commands are saved to `localStorage` (up to 200 entries) and restored automatically when the terminal is re-initialized.

### Changed
- **Exact Antigravity model selection** — resolves model families and reasoning levels against the signed-in account's model catalog and sends the selected variant through the local runtime API for new and resumed conversations. Unavailable combinations report an error instead of silently selecting another model.
- **Version bump to 1.3.1** — package metadata and release notes now report version 1.3.1.
- **OmniRoute background prewarming** — the OmniRoute gateway sidecar now starts automatically in the background as soon as the app window mounts when visible, eliminating startup delays for early chat turns.
- **Direct OmniRoute server bootstrap** — launches the precompiled server bundle directly instead of wrapping through upstream CLI layers, significantly speeding up boot time and reducing memory usage.

### Fixed
- **Settings localized in all 11 supported languages** — language and appearance, agent provider pages, CLI installation and sign-in states, usage limits, Unsloth and Antigravity now use the shared translation catalogs. Completed missing provider-form translations, localized reasoning levels and quota window labels, and formatted reset dates and API-key balances for the selected locale. Added catalog completeness checks and interface coverage across every language and all 13 providers.
- **Compact settings navigation on Linux** — long translated headings now fit the narrow navigation panel with Linux font metrics, including the Ukrainian settings title.
- **Packaged OmniRoute failed to start without better-sqlite3** — moved the OMP credential helper's eager native import onto Electron's built-in SQLite, preserving read-only access and the existing database. Fatal instrumentation/module-loading errors now fail startup promptly instead of waiting 180 seconds. Vendoring verifies reused artifacts, and packaging now boots the copied sidecar twice with API and storage-persistence checks while blocking accidental dependency resolution from the development workspace.
- **Local-provider switching and cancellation** — model refreshes ignore stale responses after switching backends, each HTTP request retains its connection settings while streaming, and the Stop button now cancels the actual OpenAI-compatible chat request.
- **Antigravity response text missing after reasoning block** — reads updated transcript steps instead of relying on append-only byte offsets, recovers truncated fields from `transcript_full.jsonl`, and waits for the completed answer. Rewritten text and reasoning snapshots replace earlier content; the renderer displays incoming answer text immediately and updates the same message on completion. A turn containing only reasoning now reports a missing-answer error rather than succeeding silently.
- **Duplicate CLI errors and answer bubbles** — stream and completion events now share message identities, and a final run failure does not repeat an error already shown during streaming.
- **Antigravity workspace matching and auto-recovery** — automatically associates conversations with the active workspace directory in Ascora ADE by matching `workspace_uris` in Antigravity's conversation database. Catches language server `project_id` mismatches and self-heals by dynamically binding the active server project ID.
- **Antigravity streaming and tool rendering** — resolved newline splitting in the runner NDJSON stream parser that previously dumped unformatted JSON blocks into chat messages. Correctly maps Antigravity `CommandLine`, `DirectoryPath`, `AbsolutePath`, and query parameters to native Ascora ADE tool cards.
- **OmniRoute chats recover automatically from interrupted agent turns** — the internal "Reached the tool-step limit" and "(no content returned)" replies are now hidden from the regular conversation and shown as collapsible reasoning progress instead. Ascora waits two to three seconds and transparently sends `Continue` with the existing task context, retrying up to three times before stopping and surfacing the final failure; other chat backends keep their existing behavior.
- **Premium VPN reconnects keep their account identity** — Ascora proactively refreshes expiring access tokens, serializes concurrent refresh attempts, and verifies the account through the required-auth profile endpoint before every connection. A Premium session can no longer be silently provisioned as anonymous and rejected by the shared 100 MB machine limit after disconnecting and reconnecting.
- **Premium traffic is attributed to the account** — traffic responses that were anonymously downgraded by older Wandrounik control panels are detected and retried after account validation. Misclassified persisted sessions are cleaned up on launch, anonymous session credentials remain usable for cleanup after a token refresh, and new Premium traffic is recorded in the account statistics instead of remaining at zero.
- **OmniRoute health checks and IPC bypass VPN interception** — replaced Electron's global `fetch` with Node's native `node:http` module for loopback connections to the OmniRoute sidecar. This prevents the Chromium network stack from routing `127.0.0.1` requests through active VPNs or system proxies, which previously caused the health endpoint to time out after 180 seconds on startup and blocked admin requests.
- **Antigravity Python bridge bundled in unpackaged resources** — `bridge.py` is bundled as an extra resource outside the virtual `app.asar` container so that Windows `python.exe` can execute it directly without encountering missing file or directory errors.
